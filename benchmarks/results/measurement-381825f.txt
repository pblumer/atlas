# Atlas measurement-feasibility capture — Milestone B slice B7
#
# This is not a performance baseline. It is the evidence for one design question:
# ADR-0305's open question, whether a business capability's declared KPIs and SLAs
# are computable from what Atlas already keeps, at volume, WITHOUT the OpenSearch
# exporter (ADR-0114) that not every installation runs. The record required that it
# be answered by measurement rather than by argument.
#
# Commit:        381825f (branch claude/modest-maxwell-4b4las, off main 5d9174e)
# Go:            go1.26.0 linux/amd64
# GOMAXPROCS:    4
# CPU:           Intel(R) Xeon(R) Processor @ 2.10GHz, 4 cores — shared cloud VM
# OS / kernel:   Linux 6.18.44-fc-v24
# Durable store: the benchmark's own temp dir on the container filesystem
# Date:          2026-09-11
#
# Each op is ONE WHOLE READING over the whole population, so ns/op is the cost of
# answering the question once. The reading is not windowed: an unbounded walk is the
# upper bound on what any window costs, which is the number the question is about.
#
# Two axes, run separately:
#   1. population  — 100 / 1k / 10k (committed default), then 100k by override
#   2. process length — 1 / 10 / 30 script tasks at a fixed 10k population
#
