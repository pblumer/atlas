Willkommen bei Atlas

Welcome to Atlas

Atlas ist eine Workflow-Engine für BPMN 2.x: Du zeichnest einen Geschäftsprozess als Diagramm, deployst ihn, und Atlas führt ihn Schritt für Schritt aus – zuverlässig, nachvollziehbar und dauerhaft gespeichert. Entscheidungen lagerst du in DMN-Tabellen aus.

Atlas is a workflow engine for BPMN 2.x: you draw a business process as a diagram, deploy it, and Atlas runs it step by step – reliably, traceably and durably stored. Decisions live in DMN tables.

Unter der HaubeUnder the hood

Atlas speichert jeden Zustandsübergang als Ereignis in einem append-only Log und baut den Zustand daraus wieder auf. Darum ist jede Instanz vollständig nachvollziehbar und übersteht Neustarts ohne Datenverlust. Neugierig aufs Warum? Siehe Console → Engine und die Architektur-Doku im Repository.

Atlas records every state transition as an event in an append-only log and rebuilds state from it. That's why every instance is fully traceable and survives restarts without data loss. Curious about the why? See Console → Engine and the architecture docs in the repository.

BPMN lernen

Learn BPMN

BPMN (Business Process Model and Notation) ist die weltweite Standardsprache für Prozessdiagramme. Das Schöne: Fachbereich und IT lesen dasselbe Bild. Du brauchst überraschend wenig, um anzufangen.

BPMN (Business Process Model and Notation) is the worldwide standard language for process diagrams. The beauty: business and IT read the same picture. You need surprisingly little to get started.

Das Vokabular in einer Minute

The vocabulary in one minute

  • Events (Kreise) – etwas passiert: Start (dünn), Zwischenereignis (doppelt), Ende (dick). Ein Prozess beginnt mit einem Start- und endet mit einem End-Event.
  • Events (circles) – something happens: start (thin), intermediate (double), end (thick). A process begins with a start and finishes with an end event.
  • Aktivitäten (Rechtecke) – Arbeit wird getan: Tasks (z. B. Service-, User-, Script-Task) und Subprozesse.
  • Activities (rounded rectangles) – work gets done: tasks (e.g. service, user, script task) and subprocesses.
  • Gateways (Rauten) – der Fluss verzweigt oder führt zusammen: exklusiv (X), parallel (+), inklusiv (O), ereignisbasiert.
  • Gateways (diamonds) – the flow splits or joins: exclusive (X), parallel (+), inclusive (O), event-based.
  • Sequenzflüsse (Pfeile) – verbinden die Elemente und geben die Reihenfolge vor.
  • Sequence flows (arrows) – connect the elements and define the order.

Dein erstes Modell

Your first model

Ein lauffähiger Prozess braucht mindestens: ein Start-Event → eine oder mehrere Aktivitäten → ein End-Event, verbunden durch Sequenzflüsse. Sobald du eine Entscheidung brauchst („wenn Betrag > 1000, dann Freigabe"), setzt du ein exklusives Gateway und schreibst die Bedingung als FEEL-Ausdruck an den Ausgangsfluss.

A runnable process needs at least: a start event → one or more activities → an end event, connected by sequence flows. As soon as you need a decision ("if amount > 1000, require approval"), add an exclusive gateway and write the condition as a FEEL expression on the outgoing flow.

Gut lesbare DiagrammeReadable diagrams

Halte den Happy Path auf einer geraden Linie. Führe Alternativen in einer eigenen Spur darüber oder darunter und lass sie an einem Join-Gateway wieder zusammenlaufen. Beschrifte die Ausgänge von Gateways. Ein Diagramm, das kompiliert, aber wie ein Kabelsalat aussieht, ist noch nicht fertig.

Keep the happy path on one straight line. Route alternatives in their own lane above or below and reconverge them at a join gateway. Label the gateway's outgoing flows. A diagram that compiles but looks like a tangle of wires isn't done yet.

DMN lernen

Learn DMN

DMN (Decision Model and Notation) trennt Entscheidungslogik vom Prozessfluss. Statt zig verschachtelte Gateways zu bauen, schreibst du die Regeln als übersichtliche Entscheidungstabelle. Fachbereiche können sie lesen und pflegen. Atlas wertet DMN über die eingebaute Decision-Engine temis (DMN 1.5 / FEEL) aus.

DMN (Decision Model and Notation) separates decision logic from the process flow. Instead of a maze of nested gateways, you write the rules as a tidy decision table. Business teams can read and maintain it. Atlas evaluates DMN through the built-in decision engine temis (DMN 1.5 / FEEL).

Eine Entscheidungstabelle lesen

Reading a decision table

Spalten links sind Eingaben (Inputs), Spalten rechts sind Ausgaben (Outputs). Jede Zeile ist eine Regel: „wenn die Inputs so aussehen, dann liefere diese Outputs". Beispiel – Rabattstufe nach Kundentyp und Bestellwert:

Columns on the left are inputs, columns on the right are outputs. Each row is a rule: "if the inputs look like this, produce these outputs". Example – discount tier by customer type and order value:

KundentypCustomer type (in) BestellwertOrder value (in) RabattDiscount (out)
"premium">= 100015%
"premium"< 100010%
"standard">= 10005%
"standard"< 10000%

Hit Policy – welche Regel gewinnt?

Hit policy – which rule wins?

  • Unique (U) – genau eine Regel darf passen. Der sichere Standard. exactly one rule may match. The safe default.
  • First (F) – die erste passende Regel von oben gewinnt. the first matching rule from the top wins.
  • Collect (C) – alle passenden Regeln, als Liste (optional summiert/min/max). all matching rules, as a list (optionally sum/min/max).
  • Any (A) – mehrere dürfen passen, müssen aber dasselbe liefern. several may match but must all produce the same result.

Using DMN in Atlas

  1. DMN-Modell im Modeler anlegen oder hochladen und deployen.
  2. Create or upload a DMN model in the Modeler and deploy it.
  3. Im Prozess eine Business-Rule-Task setzen und auf die Entscheidung verweisen.
  4. Add a business rule task in the process and reference the decision.
  5. Das Ergebnis landet als Variable in der Instanz und steuert den weiteren Fluss.
  6. The result lands as a variable in the instance and steers the rest of the flow.
  7. Ausgewertete Entscheidungen prüfst du unter Operations → Decisions.
  8. Inspect evaluated decisions under Operations → Decisions.

Prozesse designen

Design processes

Vom leeren Diagramm zum durchdachten Modell.

From an empty diagram to a well-thought-out model.

  1. Das Ziel zuerstGoal first

    Formuliere in einem Satz, was der Prozess erreichen soll und wann er fertig ist. Das bestimmt Start- und End-Event.

    State in one sentence what the process should achieve and when it's finished. That fixes the start and end events.

  2. Den Happy Path zeichnenDraw the happy path

    Die ideale Abfolge ohne Sonderfälle – eine gerade Linie von Tasks.

    The ideal sequence without special cases – a straight line of tasks.

  3. Entscheidungen & AusnahmenDecisions & exceptions

    Gateways für Verzweigungen, Boundary-Events für Timeouts/Fehler, DMN für komplexe Regeln.

    Gateways for branches, boundary events for timeouts/errors, DMN for complex rules.

  4. Daten festlegenDefine the data

    Welche Variablen trägt die Instanz? Woher kommen sie (Start-Formular, Task, Connector)?

    Which variables does the instance carry? Where do they come from (start form, task, connector)?

  5. DokumentierenDocument it

    Jedes Element hat im Details-Panel eine Documentation — direkt unter Name und ID. Schreib dort hinein, warum es den Schritt gibt, welche Regel dahintersteht und wer zuständig ist; für den Prozess selbst (nichts ausgewählt) die Zusammenfassung, die man vor dem Diagramm lesen möchte. Der Text gehört zum Modell: die Engine führt ihn nie aus, aber er überlebt Deploy, Export und jede Version — die Dokumentation bleibt also am Prozess statt in einem Extra-Dokument zu veralten. Bei einer User-Task ist er mehr als eine Notiz: die Tasks-App zeigt ihn der bearbeitenden Person über dem Formular als Arbeitsanweisung. Schreib ihn dort also an die Person, die die Aufgabe erledigt. Im Instanz-Replay steht die Doku des gewählten Elements unter seinen Eigenschaften — auch bei einem Zweig, den diese Instanz nie genommen hat.

    Every element has a Documentation field in the Details panel — right below its name and id. Put there why the step exists, the rule behind it and who owns it; for the process itself (nothing selected), the summary a reader wants before following the diagram. The text is part of the model: the engine never acts on it, but it survives deploy, export and every version — so the documentation stays with the process instead of going stale in a separate document. On a user task it is more than a note: the Tasks app shows it to the assignee above the form as the work instruction, so write that one to the person who will do the work. The instance replay shows the selected element's documentation under its properties — including for a branch this instance never took.

  6. Prüfen & aufräumenValidate & tidy

    Der Modeler validiert live. Aufgeräumtes Layout ist Teil der Arbeit, nicht Kür.

    The Modeler validates live. A tidy layout is part of the job, not a bonus.

Atlas installieren & betreiben

Installing & operating Atlas

Atlas ist ein einziges, in sich geschlossenes Binary – keine Datenbank, kein Broker, keine Laufzeit-Abhängigkeiten. Engine, HTTP-API und diese ganze Oberfläche stecken darin. Herunterladen, Prüfsumme verifizieren, starten.

Atlas is one self-contained binary – no database, no broker, no runtime dependencies. The engine, the HTTP API and this entire UI are compiled into it. Download it, verify the checksum, run it.

  • Genau ein Prozess pro Datenverzeichnis. Atlas ist eine Single-Writer-Engine – zwei Server auf demselben Verzeichnis beschädigen es.
  • Exactly one process per data directory. Atlas is a single-writer engine – two servers on the same directory will corrupt it.
  • Atlas spricht kein TLS. Vor dem Server gehört ein Reverse Proxy, der TLS terminiert, bevor jemand von aussen darauf zugreifen kann.
  • Atlas speaks no TLS. Put a TLS-terminating reverse proxy in front of it before anyone outside the host can reach it.
  • Sichere den Vault-Key. Ein Datenverzeichnis ohne seinen vault.key ist nicht wiederherstellbar – die darin gespeicherten Connector-Secrets sind dann nicht mehr lesbar.
  • Back up the vault key. A data directory without its vault.key is not recoverable – the connector secrets in it can no longer be read.

Der Arbeitszyklus

The working cycle

  1. Fachlichkeit klärenClarify the domain

    Wer löst einen Fall aus, wer arbeitet daran, wie viele sind es am Tag, wie lange darf er dauern – und was darf schiefgehen. Die letzte Frage wird am häufigsten vergessen und bestimmt am meisten am Modell.

    Who triggers a case, who works on it, how many per day, how long may it take – and what is allowed to go wrong. The last question is the one most often skipped, and the one that shapes the model most.

  2. Den Fall schneidenCut the case

    Was ist eine Instanz? Eine Bewerbung, eine Bestellung, ein Gerät – nicht „der Bewerbungsprozess“. Und: welcher Teil taucht so oft auf, dass er ein eigener, aufrufbarer Prozess sein sollte?

    What is one instance? One application, one order, one device – not "the hiring process". And: which part recurs often enough to become its own callable process?

  3. Den Datenvertrag festlegenFix the data contract

    Welche Variablen trägt eine Instanz, wer schreibt sie, wer liest sie. Schreib sie auf, bevor du modellierst – sonst schreibt das Modell sie für dich, und zwar dreimal verschieden.

    Which variables an instance carries, who writes them, who reads them. Write them down before you model – otherwise the model writes them for you, three different ways.

  4. Den Happy Path modellierenModel the happy path

    Eine gerade Linie, fünf bis neun Schritte. Wenn der Weg ohne Zwischenfälle nicht auf eine Achse passt, ist der Fall zu gross geschnitten.

    One straight line, five to nine steps. If the uneventful path does not fit on one axis, the case is cut too big.

  5. Abweichungen ergänzenAdd the deviations

    Fristen, Rückfragen, Abbrüche, ausgefallene Umsysteme. Jede Abweichung bekommt einen sichtbaren Weg im Diagramm – nicht eine Bedingung mehr in einem Gateway.

    Deadlines, queries, cancellations, systems that are down. Every deviation gets a visible path on the diagram – not one more condition inside a gateway.

  6. Umsysteme erst simulierenSimulate the systems first

    Ein Service-Task im Mockup-Modus antwortet mit Verzögerung, Ergebnis und Ausfallquote – du kannst den ganzen Ablauf durchspielen, bevor irgendeine echte Schnittstelle existiert. Die Anbindung ersetzt später genau dieses eine Element.

    A service task in mockup mode answers with a delay, a result and a failure rate – you can play the whole flow through before any real interface exists. The real connection later replaces exactly that one element.

  7. Durchspielen und testenPlay it through and test

    Erst simulieren, dann echte Instanzen mit typischen und untypischen Daten. Grenzwerte, leere Felder, der Fall, der zurückgezogen wird.

    First simulate, then real instances with typical and atypical data. Boundaries, empty fields, the case that gets withdrawn.

  8. Publizieren, betreiben, weiterentwickelnPublish, operate, evolve

    Die Applikation als Ganzes publizieren, in Operations zusehen, die nächste Version bauen – und wissen, dass laufende Instanzen ihre Version behalten, bis du sie migrierst.

    Publish the application as a whole, watch it in Operations, build the next version – knowing that running instances keep their version until you migrate them.

Handwerksregeln

Rules of the craft

  • Benenne im Imperativ.Name in the imperative. „Vertrag anlegen“, nicht „Vertragsanlage“. Ein Task ist eine Handlung; ein Ereignis ist ein Zustand („Bewerbung eingegangen“). "Create the contract", not "Contract creation". A task is an action; an event is a state ("Application received").
  • Das Diagramm ist kein Programm.The diagram is not a program. Wenn du anfängst, Gateways zu verschachteln, ist die Regel eine Entscheidung und gehört in eine Tabelle. The moment you start nesting gateways, the rule is a decision and belongs in a table.
  • Variablen sind eine öffentliche Schnittstelle.Variables are a public interface. Formulare, Skripte, Entscheidungen und Connectors lesen dieselben Namen. Benenne sie einmal richtig; ein Zielname ist immer eine Variable, nie ein Pfad mit Punkt. Forms, scripts, decisions and connectors read the same names. Get them right once; a write target is always a variable, never a dotted path.
  • Jeder Fall bekommt eine Antwort.Every case gets an answer. Ein Default-Zweig, der ins Leere läuft, ist ein Kunde, der nie wieder von dir hört. A default branch that goes nowhere is a customer who never hears from you again.
  • Fehler sind Fachlichkeit.Failure is part of the domain. „Umsystem nicht erreichbar“ ist ein Weg im Modell, kein Incident. Ein Incident ist, was du nicht vorhergesehen hast. "System unreachable" is a path in the model, not an incident. An incident is what you did not foresee.
  • Dokumentiere im Modell.Document inside the model. Das Dokumentationsfeld reist mit jedem Deploy, Export und jeder Version mit; ein Kommentar im Chat nicht. An einer User-Task ist es die Arbeitsanweisung, die im Posteingang über dem Formular steht. The documentation field travels with every deploy, export and version; a comment in a chat does not. On a user task it is the work instruction shown above the form in the inbox.
  • Zeit ist ein Ereignis, kein Warten.Time is an event, not waiting. Eine Frist ist ein Timer im Modell – sichtbar, durabel, im Replay nachvollziehbar. Kein sleep in einem Skript. A deadline is a timer in the model – visible, durable, replayable. Never a sleep in a script.
  • Rechne mit dem zweiten Versuch.Expect the second attempt. Ein Schritt, der ein Umsystem verändert, kann wiederholt werden. Gib ihm einen fachlichen Schlüssel mit, damit zweimal ausführen nicht zweimal buchen heisst. A step that changes a foreign system can be retried. Give it a business key so running twice does not mean booking twice.

Der FallThe case

Eine Bewerbung geht ein. Sie wird bestätigt und vorgeprüft; je nach Abschluss und Erfahrung folgen eine oder zwei Interviewrunden. In zehn Schritten gebaut

Built in ten steps

  1. Die Applikation anlegenCreate the application

    Zuerst die Klammer, dann der Inhalt: eine Applikation ist das, was gemeinsam publiziert, versioniert und exportiert wird. Jedes Artefakt, das du danach anlegst, gehört ihr – ein Formular ohne Applikation findet beim Publizieren niemand.

    The bracket first, the content second: an application is what gets published, versioned and exported as one. Every artifact you create afterwards belongs to it – a form without an application is one nobody finds at publish time.

  2. Das Start-Formular ist der DatenvertragThe start form is the data contract

    Was hier nicht erfasst wird, existiert im Prozess nicht. Zwei Felder verdienen einen zweiten Blick: abschluss und erfahrungJahre sind die Eingaben der DMN-Entscheidung, und email wird später der Korrelationsschlüssel für den Rückzug. Namen also nicht nach Gefühl vergeben – drei andere Artefakte lesen sie.

    What is not captured here does not exist in the process. Two fields deserve a second look: abschluss and erfahrungJahre are the DMN decision's inputs, and email later becomes the correlation key for the withdrawal. So do not name them by feel – three other artifacts read them.

    { "key": "abschluss", "type": "select", "label": "Höchster Abschluss",
  "values": [ { "label": "Master", "value": "master" }, … ] }
  3. Die Regel in eine TabelleThe rule into a table

    „Master mit fünf Jahren: zwei Runden; Studium mit zwei Jahren: eine Runde; Lehre mit fünf: eine Runde; sonst Absage“ – als Gateway-Kaskade wäre das vier verschachtelte Rauten. Als DMN-Tabelle ist es vier Zeilen, die HR selbst pflegen kann. Der Clou steht in der zweiten Ausgabespalte: runden ist eine Liste, keine Zahl.

    "Master with five years: two rounds; a degree with two years: one round; apprenticeship with five: one round; otherwise reject" – as a gateway cascade that is four nested diamonds. As a DMN table it is four rows HR can maintain. The trick is in the second output column: runden is a list, not a number.

    abschluss (in)erfahrungJahre (in)empfehlung (out)runden (out)
    "master">= 5"interview"["Fachinterview", "Führungsinterview"]
    "master", "bachelor">= 2"interview"["Fachinterview"]
    "lehre">= 5"interview"["Fachinterview"]
    ––"absage"[]

    Hit-Policy FIRST: die Regeln dürfen sich überlappen, die erste passende gewinnt, und die letzte Zeile fängt alles auf – kein Fall bleibt ohne Antwort. Der Business-Rule-Task ruft die Tabelle auf und legt das Ergebnis in einer Variablen ab:

    Hit policy FIRST: rules may overlap, the first match wins, and the last row catches everything – no case is left without an answer. The business rule task calls the table and puts the result in a variable:

    <businessRuleTask id="pruefung" name="Vorprüfung">
  <extensionElements>
    <zeebe:calledDecision decisionId="bw-vorpruefung" resultVariable="pruefung"/>
    <zeebe:ioMapping>
      <zeebe:input source="=abschluss" target="abschluss"/>
      <zeebe:input source="=erfahrungJahre" target="erfahrungJahre"/>
    </zeebe:ioMapping>
  </extensionElements>
</businessRuleTask>

    pruefung enthält danach { empfehlung: "interview", runden: ["Fachinterview", "Führungsinterview"] }.

    pruefung then holds { empfehlung: "interview", runden: ["Fachinterview", "Führungsinterview"] }.

    StolpersteinGotcha

    Atlas löst eine Entscheidung über ihren Namen auf. Halte id und name der <decision> identisch, sonst findet der Deploy sie nicht und weist die ganze Applikation zurück.

    Atlas resolves a decision by its name. Keep the <decision>'s id and name identical, otherwise the deploy cannot find it and refuses the whole application.

  4. Auf das Ergebnis verzweigenBranch on the result

    Das Gateway entscheidet nichts mehr – es liest nur, was die Tabelle entschieden hat. Der Default-Zweig führt zur Absage: was nicht ausdrücklich eingeladen wird, wird abgesagt.

    The gateway decides nothing any more – it only reads what the table decided. The default flow leads to the rejection: whatever is not explicitly invited gets a rejection.

    <sequenceFlow id="f_gw_interviews" name="einladen"
              sourceRef="gw_pruefung" targetRef="interviews">
  <conditionExpression>= pruefung.empfehlung = "interview"</conditionExpression>
</sequenceFlow>
  5. Zerlegen: das Interview wird ein eigener ProzessDecompose: the interview becomes its own process

    Eine Interviewrunde ist ein Ablauf für sich: Termin, Gespräch, Feedback, Frist. Sie kommt mehrfach vor. Also wird sie ein eigenständig deployter Prozess (bw-interview), den eine Call-Activity aufruft – einzeln testbar, einzeln versionierbar, später auch von anderen Prozessen nutzbar.

    One interview round is a flow in itself: schedule, conversation, feedback, deadline. It occurs more than once. So it becomes a separately deployed process (bw-interview) that a call activity calls – testable on its own, versionable on its own, usable by other processes later.

    Der Aufruf ist ein Vertrag, kein gemeinsamer Datentopf. Beide propagateAll…-Flags stehen auf false, und die ioMapping sagt genau, was rein- und was rausgeht:

    The call is a contract, not a shared bucket of data. Both propagateAll… flags are false, and the ioMapping states exactly what goes in and what comes out:

    <zeebe:calledElement processId="bw-interview"
    propagateAllParentVariables="false" propagateAllChildVariables="false"/>
<zeebe:ioMapping>
  <zeebe:input  source="=name"   target="name"/>
  <zeebe:input  source="=stelle" target="stelle"/>
  <zeebe:input  source="=runde"  target="runde"/>
  <zeebe:output source="=bewertung" target="bewertung"/>
</zeebe:ioMapping>

    Ohne diese Flags erbt der Teilprozess alles, was der Fall gerade mit sich trägt, und gibt alles zurück. Das funktioniert – bis jemand im Teilprozess eine Variable umbenennt und der Aufrufer stillschweigend kaputtgeht.

    Without those flags the child inherits everything the case happens to carry and hands everything back. That works – until someone renames a variable in the child and the caller breaks silently.

  6. Wiederholen: einmal je RundeRepeat: once per round

    Wie oft der Teilprozess läuft, hat die DMN-Tabelle entschieden. Die Multi-Instance iteriert über pruefung.runden, seriell – die zweite Runde ergibt erst nach dem Feedback der ersten Sinn – und sammelt jede Rückgabe in bewertungen:

    How often the child runs was decided by the DMN table. The multi-instance iterates over pruefung.runden, sequentially – a second round only makes sense after the first one's feedback – and collects each return value into bewertungen:

    <multiInstanceLoopCharacteristics isSequential="true">
  <extensionElements>
    <zeebe:loopCharacteristics inputCollection="=pruefung.runden" inputElement="runde"
        outputCollection="bewertungen" outputElement="=bewertung"/>
  </extensionElements>
</multiInstanceLoopCharacteristics>

    Eine dritte Runde einzuführen heisst jetzt: eine Zeile in der Tabelle ändern. Das Modell bleibt, wie es ist. Genau dafür trennt man Regel und Ablauf.

    Introducing a third round now means: change one row in the table. The model stays as it is. That separation of rule and flow is the whole point.

    Der Vertrag gilt auf jedem WegThe contract holds on every path

    Der Teilprozess hat zwei Enden: Feedback erfasst – oder Frist abgelaufen. Beide schreiben eine bewertung; das Fristende schreibt eine mit „nein“ und einer Notiz. Fände die Sammelstelle beim Zusammenführen nichts vor, hätte die Liste ein Loch – und die Auswertung rächte sich einen Schritt später.

    The child has two ends: feedback captured – or deadline expired. Both write a bewertung; the deadline writes one with "no" and a note. If the collector found nothing there, the list would have a hole – and the evaluation one step later would pay for it.

  7. Verdichten, damit ein Mensch entscheiden kannCondense it so a human can decide

    Eine Liste von Objekten ist keine Entscheidungsgrundlage. Ein Inline-Script macht daraus einen Satz – erst das Urteil über alle Runden, dann jede Runde einzeln:

    A list of objects is not something to decide on. An inline script turns it into one sentence – first the verdict over all rounds, then each round:

    = (if every b in bewertungen satisfies b.empfehlung = "ja"
     then "Alle Runden empfehlen: ja" else "Nicht alle Runden empfehlen")
  + " — "
  + string join(for b in bewertungen
                return b.runde + ": " + b.empfehlung + " (" + b.notiz + ")", " | ")

    Das Ergebnis steht im Formular der Aufgabe Einstellung entscheiden. Und weil ein Mensch eine Aufgabe auch mal liegen lässt, hängt ein nicht unterbrechender Boundary-Timer (P3D) daran, der nebenher eine Erinnerung auslöst, ohne die Aufgabe abzubrechen. Eine unterbrechende Frist wäre hier fachlich falsch: eine Bewerbung darf nicht verfallen, sie soll nur nicht liegen bleiben.

    The result shows up in the form of the decide on hiring task. And because a human does leave a task sitting, a non-interrupting boundary timer (P3D) hangs on it, firing a reminder alongside without cancelling the task. An interrupting deadline would be wrong here: an application must not expire, it should just not be forgotten.

  8. Umsysteme: erst simulieren, dann anbindenForeign systems: simulate first, connect later

    Vier Schritte reden mit der Aussenwelt: Eingangsbestätigung, Erinnerung, Absage und „Vertrag im HR-System anlegen“. Keiner davon braucht für dieses Kapitel eine echte Anbindung – sie laufen im Mockup-Modus, in dem die Engine das Umsystem selbst simuliert: mit Antwortzeit, geskripteter Antwort und Ausfallquote.

    Four steps talk to the outside world: acknowledgement, reminder, rejection and "create the contract in the HR system". None of them needs a real connection for this chapter – they run in mockup mode, where the engine simulates the system itself: response time, scripted answer, failure rate.

    <atlas:mockupConnector minDuration="PT1S" maxDuration="PT4S"
    resultExpression="={ vertragsnummer: &quot;V-2026-0815&quot; }"
    resultVariable="vertrag"
    failRate="0.2" errorCode="HR_UNERREICHBAR"/>

    So läuft die Applikation end-to-end, bevor eine einzige Schnittstelle existiert – und der Fachbereich sieht den echten Ablauf statt eines Foliensatzes. Steht die REST- oder Mail-Anbindung später, ersetzt sie genau dieses eine Element; der Rest des Modells bleibt unberührt.

    That makes the application run end to end before a single interface exists – and the business sees the real flow instead of a slide deck. When the REST or mail connection arrives later, it replaces exactly that one element; the rest of the model is untouched.

  9. Wenn das Umsystem ausfälltWhen the system is down

    Die failRate von 0.2 ist kein Gag: in etwa jedem fünften Lauf wirft „Vertrag im HR-System anlegen“ den Fehler HR_UNERREICHBAR. Eine Error-Boundary fängt ihn und macht daraus eine Aufgabe für einen Menschen – „Vertrag manuell anlegen“.

    The failRate of 0.2 is not a joke: in roughly every fifth run "create the contract in the HR system" throws HR_UNERREICHBAR. An error boundary catches it and turns it into a task for a human – "create the contract by hand".

    Das ist der Unterschied zwischen einem modellierten Fehlerweg und einem Incident: der Fall ist nicht steckengeblieben, er ist zugewiesen. Ein Incident bleibt das, was du nicht vorhergesehen hast – und dafür ist Operations da.

    That is the difference between a modelled failure path and an incident: the case is not stuck, it is assigned. An incident stays what you did not foresee – and that is what Operations is for.

  10. Was jederzeit passieren kannWhat can happen at any time

    Ein Rückzug hängt an keinem Schritt – er kann vor der Vorprüfung kommen, zwischen zwei Interviews, nach der Zusage. Genau dafür gibt es den Event-Subprozess: er hängt am ganzen Prozess. Sein Start ist unterbrechend, beendet den Fall also und räumt eine offene Interview-Aufgabe aus dem Posteingang.

    A withdrawal hangs on no step – it can arrive before the screening, between two interviews, after the offer. That is exactly what an event subprocess is for: it hangs on the whole process. Its start is interrupting, so it ends the case and clears an open interview task out of the inbox.

    <message id="msg_rueckzug" name="bw-rueckzug">
  <extensionElements><zeebe:subscription correlationKey="=email"/></extensionElements>
</message>

    Der Korrelationsschlüssel ist die E-Mail-Adresse aus dem Start-Formular – deshalb war Schritt 2 wichtiger, als er aussah. Auslösen lässt sich die Nachricht von aussen:

    The correlation key is the e-mail address from the start form – which is why step 2 mattered more than it looked. The message can be published from outside:

    curl -X POST /api/v1/messages -H 'Content-Type: application/json' \
  -d '{"name":"bw-rueckzug","correlationKey":"ada@example.org"}'
    Scope-RegelScope rule

    Was ein Subprozess in seinem eigenen Scope schreibt, verschwindet mit ihm. Der Vermerk status = "zurückgezogen" überlebt nur, weil eine ioMapping-Ausgabe am Subprozess ihn herausreicht.

    What a subprocess writes in its own scope disappears with it. The note status = "zurückgezogen" survives only because an ioMapping output on the subprocess hands it out.

  11. Publizieren – alles auf einmalPublish – everything at once

    Beim Publizieren prüft Atlas die Applikation als Ganzes: löst jede DMN-Referenz auf, bindet die Entscheidungen an die Business-Rule-Tasks, kompiliert beide Prozesse. Ein einziger Fehler – eine Entscheidung, die kein Modell liefert – weist den ganzen Bundle-Deploy zurück, statt ein halbes Release zu hinterlassen. Danach steht ein Release mit einer Versionsnummer und einer Momentaufnahme dessen, was ausgeliefert wurde.

    Publishing validates the application as a whole: every DMN reference is resolved, the decisions are bound to the business rule tasks, both processes are compiled. A single failure – a decision no model provides – refuses the entire bundle deploy instead of leaving half a release behind. What you get is a release with a version number and a snapshot of what shipped.

    POST /api/v1/applications                      → applicationId
POST /api/v1/dmn-models?name=bw-vorpruefung    → modelRef
POST /api/v1/dmnrefs        { projectId, modelRef }
POST /api/v1/forms          { id, projectId, schema }   × 3
POST /api/v1/drafts?projectId=…   <bewerbung.bpmn>, <interview.bpmn>
POST /api/v1/applications/{id}/publish         → definitions + release

    Genau diese Reihenfolge geht auch der Knopf oben. Laufende Instanzen bleiben auf ihrer Version, bis du sie migrierst – ein Release ändert nie einen Fall, der schon unterwegs ist.

    That is the exact order the button above follows. Running instances stay on their version until you migrate them – a release never changes a case that is already under way.

Jetzt ausprobieren

Now try it

  1. Master, 6 Jahre installieren (oben) → im Posteingang wartet Feedback erfassen, Runde „Fachinterview“. Abschicken → dieselbe Aufgabe kommt ein zweites Mal, jetzt für „Führungsinterview“. Das ist die serielle Multi-Instance, von innen gesehen.
  2. Master, 6 years installed (above) → the inbox holds capture feedback for the round "Fachinterview". Submit → the same task appears a second time, now for "Führungsinterview". That is the sequential multi-instance, seen from the inside.
  3. Danach Einstellung entscheiden: das Fazit im Formular ist das Ergebnis des string join aus Schritt 7. Zusagen → mit etwas Pech (jeder fünfte Lauf) erscheint Vertrag manuell anlegen – der Fehlerweg, live.
  4. Then decide on hiring: the summary in the form is the output of the string join from step 7. Say yes → with a bit of bad luck (every fifth run) create the contract by hand shows up – the failure path, live.
  5. Eine zweite Bewerbung mit kein Abschluss, 0 Jahre installieren → sie läuft ohne jede Aufgabe direkt in die Absage. In Operations siehst du im Replay, welche DMN-Regel gegriffen hat.
  6. Install a second application with no degree, 0 years → it runs straight into the rejection with no task at all. In Operations the replay shows which DMN rule fired.
  7. Den Rückzug auslösen (curl aus Schritt 10, mit der E-Mail der Bewerbung) → der Fall endet in „Zurückgezogen“, eine offene Aufgabe verschwindet aus dem Posteingang.
  8. Trigger the withdrawal (the curl from step 10, with the application's e-mail) → the case ends in "withdrawn" and an open task disappears from the inbox.

Weiterbauen

Keep building

  • Echt anbinden: „Eingangsbestätigung senden“ an einen Mail-Connector, „Vertrag im HR-System anlegen“ an einen REST-Connector – je ein Element, sonst nichts.
  • Connect for real: point "send acknowledgement" at a mail connector and "create the contract" at a REST connector – one element each, nothing else.
  • Eine dritte Runde für Führungsstellen: eine Zeile in der DMN-Tabelle.
  • A third round for leadership roles: one row in the DMN table.
  • Anschluss ans Onboarding: „Eingestellt“ startet den Onboarding-Prozess – dort fängt der nächste Lebenszyklus an.
  • Hand over to onboarding: "hired" starts the onboarding process – where the next lifecycle begins.
  • Version 2 bauen und in Operations zusehen, wie laufende Instanzen auf Version 1 bleiben, bis du sie migrierst.
  • Build version 2 and watch in Operations how running instances stay on version 1 until you migrate them.
